# STM32F103 智能环境检测节点 OTA 固件升级系统

## 项目简介
本项目基于 STM32F103C8T6 设计了一套**三级容错架构的 OTA 固件升级系统**，采用 CAN 总线实现本地固件分发，外置 W25Q32 SPI Flash 作为固件中转存储，具备完整的完整性校验、升级失败回滚、按键出厂恢复等容错机制。系统采用分层驱动与状态机设计，可无缝集成至 FreeRTOS 智能环境检测项目，并支持扩展 ESP8266 + MQTT 实现远程网络升级。

## 硬件平台
- **主控芯片**：STM32F103C8T6（Cortex-M3 内核，64KB 内部 Flash，20KB SRAM）
- **外置存储**：W25Q32（4MB SPI Flash，用于固件中转缓存与元数据存储）
- **通信接口**：CAN 总线（主升级通道）、UART（调试日志 / 预留升级通道）、SPI（Flash 驱动）
- **交互外设**：用户按键（上电触发出厂恢复）
- **扩展支持**：ESP8266 WiFi 模组（用于后续 MQTT 远程网络升级）

## Flash 地址分区设计
### 内部 Flash 分区（STM32F103C8T6，起始地址 0x08000000）
| 分区名称 | 起始地址 | 结束地址 | 大小 | 功能说明 |
|---------|---------|---------|------|---------|
| Bootloader 引导区 | 0x08000000 | 0x08003FFF | 16KB | 启动引导、升级判断、固件烧录、程序跳转 |
| 出厂恢复程序 | 0x08004000 | 0x080097FF | 22KB | 兜底固件，按键触发启动，用于升级失败救砖 |
| 主应用程序区 | 0x08009800 | 0x0800EFFF | 22KB | 用户业务程序（智能环境检测主程序运行区） |
| 升级标志区 | 0x0800F000 | 0x0800F7FF | 2 页 | 双页独立存储升级标志与校验值，防止单页损坏导致升级异常 |

### 外置 W25Q32 分区（4MB，起始地址 0x000000）
| 分区名称 | 起始地址 | 大小 | 功能说明 |
|---------|---------|------|---------|
| 固件元数据区 | 0x000000 | 8 字节 | 存储固件目标烧录地址、固件大小信息 |
| 固件缓存区 | 0x001000 | 最大 22KB | 暂存接收到的新固件，等待 Bootloader 写入内部 Flash |

## 核心功能与工作流程

### 1. 上电启动引导流程
系统上电后默认从 0x08000000 启动 Bootloader，执行以下逻辑：
1. 读取升级标志区的校验值，若校验区未初始化则自动重建，本次不执行升级
2. 读取升级标志位，判断是否需要执行固件更新
3. 上电前 3 秒检测用户按键，按下则进入出厂恢复模式
4. 根据状态执行对应操作：
   - **无升级**：直接跳转至主应用程序（0x08009800）
   - **有升级**：从 W25Q32 读取固件，校验合法性后写入内部 Flash，完成后跳转主程序
   - **出厂恢复**：直接跳转至出厂兜底程序（0x08004000）

### 2. CAN 总线升级流程（当前已实现）
采用「上位机分发 → 节点接收缓存 → Bootloader 最终烧录」的三段式升级架构：
1. 上位机程序接收串口升级指令，通过 CAN 总线向节点发送升级请求命令（`qwe`）
2. 节点主应用程序（0x08009800）通过 CAN 接收到升级指令，进入升级接收状态
3. 上位机读取本地固件，以每包 8 字节通过 CAN 总线分片发送
4. 节点主程序持续接收 CAN 数据包，拼接缓存至 SRAM 缓冲区
5. 固件传输完成后，上位机发送固件 CRC32 校验值
6. 节点计算接收固件的 CRC 值，与上位机下发值对比校验
7. 校验通过后，节点擦除 W25Q32 对应扇区，写入固件元数据与完整固件
8. 节点写入内部 Flash 升级标志位，执行系统软复位
9. 复位后 Bootloader 检测到升级标志，从 W25Q32 读取固件
10. 校验固件栈顶地址与复位向量合法性，确认是有效 Cortex-M 固件
11. 擦除内部 Flash 应用区，将固件逐页写入内部 Flash
12. 烧录完成后清除升级标志，自动跳转至新主应用程序，升级完成

### 3. 按键出厂恢复机制
- 上电启动 Bootloader 的前 3 秒内，按下指定按键可触发出厂恢复模式
- 系统直接跳转至 0x08004000 处的出厂固件，无需擦除当前应用
- 适用于升级失败、应用程序损坏等极端场景的设备救砖
- 出厂程序预留串口升级接口，可按需扩展固件烧录能力

### 4. 安全校验与容错设计
- **固件合法性校验**：烧录前校验固件栈顶地址、复位中断向量，确保是有效的 ARM Cortex-M 程序
- **完整性校验**：采用 CRC32 算法校验固件整体数据，防止传输过程中数据损坏
- **双页标志位设计**：升级标志与校验值分属两个独立 Flash 页，避免单页擦写异常导致系统变砖
- **外置 Flash 中转**：固件先存入外置 Flash 再烧录内部，避免传输中断导致应用程序损坏
- **干净跳转机制**：跳转前关闭所有中断、复位外设与时钟树，避免应用程序运行异常

## 技术亮点
1. **三级容错架构**：Bootloader + 出厂兜底固件 + 主应用，多重保障设备可用性
2. **状态机编程**：升级全流程采用有限状态机管理，逻辑清晰，鲁棒性强
3. **驱动分层抽象**：Flash、CAN、SPI 等底层驱动与业务逻辑分离，便于移植扩展
4. **工业级容错**：双页标志位、外置缓存、出厂恢复三重防砖机制
5. **可扩展性强**：预留网络升级接口，可快速对接 MQTT 远程升级方案

## 后续扩展：MQTT 远程网络 OTA 方案
基于现有架构，可快速扩展 ESP8266 WiFi 模组实现远程网络升级，**完全复用现有 Bootloader、W25Q32 驱动与 Flash 分区设计**，仅需在应用层增加 MQTT 通信逻辑。

### 方案架构
- **云端**：MQTT 服务器（如 EMQX）+ 固件版本管理服务
- **设备端**：ESP8266 连接 WiFi 接入 MQTT；主程序基于 FreeRTOS 创建独立升级任务
- **升级通道**：MQTT 协议分片传输固件，与现有 CAN 升级通道并存

### 升级流程
1. 设备上电后通过 ESP8266 连接 WiFi 与 MQTT 服务器，订阅设备专属升级主题
2. 云端发布新版本固件信息（版本号、大小、CRC 值），设备对比版本号判断是否升级
3. 设备确认升级后，云端分片发送固件数据（建议每包 1024 字节）
4. 设备接收固件数据，依次写入 W25Q32 Flash 缓存区
5. 固件接收完成后，设备计算 CRC 并与云端下发值对比
6. 校验通过后，设置升级标志位，执行系统重启
7. Bootloader 自动完成固件烧录与跳转，实现远程无感升级

## 使用说明
1. 编译 Bootloader 程序，烧录至内部 Flash 0x08000000 地址
2. 编译出厂恢复程序，烧录至内部 Flash 0x08004000 地址
3. 编译主应用程序，可通过 CAN 升级或直接烧录至 0x08009800 地址
4. **升级操作**：上位机发送升级指令，等待固件传输与设备自动重启
5. **出厂恢复**：上电后 3 秒内按下按键，系统自动进入出厂固件
